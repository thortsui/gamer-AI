章節: §1 每次場景切換的第一件事
適用: 全部
---

【基礎確認：場景一換，先確認自己是什麼狀態】（2026-09-21 使用者定）
場景切換（大廳↔關卡↔面板）的第一步永遠是基礎確認。程式偵測到場景換了（你標的區變了，或畫面上的字整批換掉）會叫你做，花一輪回答：
```json
{"t":"基礎確認","視角":"水平/抬頭N度/低頭N度","人稱":"第三/第一",
 "游標":"解鎖/被鎖住","區":"你現在在哪","看到":"畫面上最重要的字或東西"}
```
結果存進 `記憶/基礎確認.jsonl`。

【一律用第三人稱】（2026-09-21 使用者）
場地允許就用第三人稱：看得到背影、游標自由、點得到 UI。

【游標狀態最重要】（09/21 實測同一顆進場按鈕 1868 次：第三人稱生效 58%、第一人稱 35%）
- 第三人稱、沒按右鍵 → 游標自由 → 點得到 UI。
- 第一人稱，或按住右鍵轉視角 → 游標被鎖在畫面正中央 → 點擊打到 3D 世界，UI 收不到。
- 看法：畫面下方中央有自己的背影＝第三人稱、解鎖；中央有準心、看不到自己＝第一人稱、多半鎖住；不確定就滾輪 -3 拉遠，看到背影再點。
- 沒有準心時的測法（2026-09-21 使用者教的）：送很小的轉視角 `{"t":"look","dx":40,"dy":0}`，下一輪畫面跟著轉了＝游標被鎖（第一人稱）；幾乎沒變＝游標自由，可以點 UI。看到準心或小轉就跟著動，都算鎖住。

【有些遊戲用畫面正中間的十字代替滑鼠】（2026-09-23 使用者教的）
十字不一定代表鎖住。把十字對準一顆按鈕按一次左鍵（`{"t":"click","x":0.5,"y":0.5}`）：有反應＝十字游標模式，以後就這樣點（這種模式拉遠沒用）；沒反應＝真的鎖住，再走拉遠那條路。沒試過這一下之前不要認定「有十字＝點不到」。

【滾輪】-3＝拉遠＝往第三人稱（準心消失、看得到背影）；+3＝拉近＝往第一人稱。09/22 實測有準心時 -3 只有 47% 成功。拉不動時：
1. 連做兩次 `-3`。
2. 還有準心 → 試十字游標模式。
3. 還是沒反應 → 這個場地可能鎖死第一人稱：不要再想點 UI，改用走位、轉視角、站上觸發區；同一個狀況卡住幾分鐘就退出重進（見「卡住就自己重開遊戲」）。

【點任何按鈕之前的檢查順序】（09/22：點了沒生效的 70% 是被面板擋住）
1. 有沒有面板／彈窗／半透明遮罩擋住？有就先關（叉叉、「知道了」、esc）。線索：中央大塊面板底色、四周變暗、出現「關閉／叉叉／知道了／繼續」、場景被蓋掉一半以上。
2. 是不是第一人稱（有準心）？是就先滾輪拉遠。
3. 都沒問題才點。

【怎麼分辨 UI 還是場景裡的招牌】
轉一下視角（`{"t":"look","dx":100}`）：那行字位置完全沒動＝UI，可以點；跟著畫面移動＝3D 招牌，要走過去。

【基礎技藝 vs 遊戲記憶】
基礎技藝＝換遊戲照樣成立的（視角控制、游標狀態、UI／場景分辨、先確認再動手），才寫進核心的基礎操作。遊戲記憶＝只對這個遊戲成立的（某顆按鈕在哪、踏板長什麼樣、大動作與它的步驟），寫進 `專案/<遊戲>/記憶/`。大動作一律算遊戲記憶。
