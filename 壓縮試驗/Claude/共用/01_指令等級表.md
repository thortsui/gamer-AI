【指令有等級：高的優先，抵觸的低階規則直接作廢】（2026-09-23 使用者定）
同級抵觸時後訂的優先（使用者的「更正」就是後訂）。程式用這張表審核你自己訂的規則，抵觸的刪掉，記在 `記憶/規則審核.md`。

**第 0 級：鐵律**
- 不准花任何錢（Robux、購買、解鎖、升級、付費復活）；付費視窗只能按 esc。免費復活（隊友救援、按 E 復活、等倒數）可以做。
- `s` 只寫畫面上真的看得到的東西，不形容、不推測。
- 只輸出一個 JSON。
- 絕對不能進錯遊戲；重進前比對【你記過的遊戲身分】。
- 核心文檔不能被單一遊戲的內容污染。
- 不查 YouTube、不查 wiki（09/16）。

**第 1 級：使用者的強制指令**
1. 場景一換（大廳↔關卡↔面板），第一步永遠是「基礎確認」（09/21）。
2. 一律用第三人稱；看得到自己的背影才是正常姿勢（09/18、09/21）。
3. 有些遊戲拿畫面正中央的十字當滑鼠：先把十字對到按鈕上按左鍵試一次，沒反應才算真的鎖住（09/23）。
4. 不在局內、在同一個狀況卡住（無法移動／找不到出口或進場路／滑鼠不見、游標鎖住解不開／按鈕按不動）就直接離開重進：esc → l → enter → 藍色箭頭。不用等「完全動不了」、不用等許可。「確定要離開遊戲？」出現時按 enter 或點「離開」（09/23）。
5. 每次登入／重進，先確認完「開場三件事」（09/18）。
7. 進大廳第一件事是找「開始遊戲」（09/19）。
8. 一個任務預算五分鐘，超過就停下來檢討、換做法（09/19）。
9. 走過去之前，先在畫面上把目標指出來（09/19）。
10. 新地圖先畫地圖，地圖排最前面；兩種標點一定要有（09/19）。
11. 同一顆按鈕點第二次就記進按鈕簿（09/18）；按完每一顆 UI 一定要讀字（09/20）。
12. 很多 UI 是「站」出來的，不是點出來的（09/18）。
13. 三層分工：快思只切現在這個大動作；慢想排大動作序列（09/20）。快思直接給前後三步的動作（`步:[①②③]`，每步附 a 與「成」）；反射只檢查上一步有沒有正常執行（`ok`），不決定動作：做成了程式做下一步，沒做成換快思（09/29，取代 09/20）。
14. 步數預算：一步最多兩輪，超支扣 3 分並當場檢討（09/21、09/22）。
15. 同一串操作做過兩三次就錄成程式；最終除非特殊狀況幾乎不用問模型（09/15、09/18）。
16. 檢討時從頭看每一個小動作的紀錄，不憑印象（09/20）。
17. 目標自己訂，訂了就要做到；每一局分數歸零（09/13）。
18. 視角以水平儀的度數為主，畫面只是輔助（09/14）。
19. 大動作屬於「遊戲記憶」；基礎確認、視角、UI 判別才是「基礎技藝」（09/21）。
20. 死亡不扣分，只做死亡檢討；不要因為怕死就不進關卡（09/23）。
21. 同一種壞結果一再發生，要先錄影再檢討：從頭看整段，找出第幾秒出事，寫成「開局第 N 秒：做 X」，再驗證（09/23）。
22. 用工具就是在做事（點字、這步做完、寫步驟、記知識、基礎確認、標點…），不是空轉，多用。但小動作要直接做完：一個小步驟最多兩輪，超過每輪 −20；想好要做什麼，那一輪就要把動作送出去，只送工具不送動作＝「想了卻沒做」−20（09/29）。
23. 【上一步】會攤開：你原本想怎麼做、送了什麼、實際按下去的是什麼（被改或被擋會寫）、程式替你做了什麼（例如自己按 esc、壓平視角、後退）。畫面突然變了，先看是不是程式做的（09/29）。
