適用: 全部

【基礎確認：場景一換，先確認自己是什麼狀態】
2026-09-21 使用者定：場景切換（大廳↔關卡↔面板）第一步永遠是「基礎確認」。確認完再做事。
程式偵測到場景換了（區變或字整批換）會叫你做，花一輪回答五件事：
{"t":"基礎確認","視角":"水平/抬頭N度/低頭N度","人稱":"第三/第一","游標":"解鎖/被鎖住","區":"你現在在哪","看到":"畫面上最重要的字或東西"}
結果存進 `記憶/基礎確認.jsonl`，跟步驟日誌分開。

【游標狀態與十字游標】
09/21 統計：第三人稱點 UI 生效率 58%，第一人稱 35%。差別在游標是否被鎖。
- 第三人稱、沒按右鍵 → 游標自由 → 點擊進得去 UI ✅
- 第一人稱或按住右鍵 → 游標鎖在中央 → 點擊打到 3D 世界，UI 收不到 ❌
- 不確定就 `滾輪 -3` 拉遠，看到背影再點。

2026-09-23 使用者教：有些遊戲用畫面正中央十字代替滑鼠。看到十字先分清：
- 十字游標模式：轉視角時十字固定、畫面動；對準按鈕按左鍵（{"t":"click","x":0.5,"y":0.5}）有反應。此模式拉遠無效。
- 真鎖住：十字對按鈕按左鍵沒反應，需拉遠成第三人稱。
分辨法：對準按鈕按一次左鍵，有反應＝十字即滑鼠；沒反應＝真鎖住。

【UI 與場景招牌分辨】
轉視角（如 {"t":"look","dx":100}）看字是否移動：
- 位置沒動 → UI，可點。
- 跟著畫面動 → 3D 招牌，點沒用，要走過去。
（09/21 實測：「開始遊戲」框中心固定 → 是 UI。）

【基礎技藝 vs 遊戲記憶】
- 基礎技藝＝換遊戲照樣成立（視角、游標、UI/場景分辨、先確認再動）。
- 遊戲記憶＝只對這遊戲成立（按鈕位置、踏板樣貌、大動作步驟）。
大動作一律算遊戲記憶，寫進 `專案/<遊戲>/記憶/`；基礎確認寫進核心基礎操作。

【一律用第三人稱】
2026-09-21 使用者：只要允許就用第三人稱（游標自由、點得到 UI）。第一人稱無好處且游標鎖住。
09/22 實測：看得到背影僅 18 輪，有準心 191 輪。幾乎整晚第一人稱導致無進展。

【滾輪：拉遠成功率約一半】
- 滾輪 -3 ＝ 拉遠（準心消失、見背影）；+3 ＝ 拉近（出現準心）。
- 09/22 實測：有準心時做 -3 共 121 次，成功僅 57 次（47%）。
拉不動時順序：
1. 連做兩次 -3。
2. 仍有準心 → 試「十字游標模式」（對準按左鍵）。
3. 仍沒反應 → 場地鎖死第一人稱，別再點 UI，改用走位與轉視角；卡住幾分鐘就退出重進。

【點按鈕前：先檢查有沒有東西擋住】
09/22 實測：點沒生效 368 次中 261 次（70%）有面板擋住。順序固定：
1. 有面板／彈窗／遮罩擋住？→ 先關掉（叉叉、知道了、esc）。
2. 是第一人稱（有準心）？→ 先滾輪拉遠。
3. 兩件沒問題，才點按鈕。
擋住線索：中央大塊面板、四周變暗、出現關閉/繼續按鈕、場景被蓋一半以上。

【確認游標鎖住：動滑鼠看是否回中央】
2026-09-21 使用者教：移動滑鼠若停在正中央＝第一人稱（游標鎖住）。
你看不到游標，用等效測法：
1. 送小轉視角（如 {"t":"look","dx":40,"dy":0}）。
2. 畫面跟著轉 → 游標鎖住（第一人稱）；畫面沒變 → 游標自由（第三人稱，可點 UI）。
此法比找準心可靠。看到準心或小幅轉視角畫面就動，都算鎖住。
鎖住時：先滾輪 -3 兩次；仍鎖住則別點 UI，改用走位、轉視角、站觸發區。
