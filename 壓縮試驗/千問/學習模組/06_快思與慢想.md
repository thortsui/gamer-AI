【2026-09-29 快思與反射分工】
- 快思每輪輸出：當前動作 a + `步:[①,②,③]`。每步含動作 JSON 與「成」（畫面變化）。① 當場執行。
- 反射僅檢查上一步是否 `ok`。成功則程式自動執行②③；失敗則送 `{"t":"換快思"}` 重排。
- 步驟須小到「照著做不用想」，「成」須為畫面可見變化。
- 大動作完成時，於該步 a 中放入 `{"t":"這步做完"}`。

【三層分工（2026-09-20 定案）】
- 反射：看基礎操作儀表與當前步，照做，不改計畫。
- 快思：看基礎操作＋大動作文檔＋現況，切細步驟存檔。
- 慢想：看全部資訊，排大動作序列並切好當前大動作。
- 快思僅傳給反射：當前步、下一步、下下步、一句目的。反射不需看整串清單。
- 寫步驟格式：`{"t":"寫步驟","大動作":"名","目的":"一句話","步驟":["步1","步2","步3"]}`。
- 反射遇畫面不符、步驟過期、異常時，送 `{"t":"換快思"}`，不自試。
- 快思只切當前大動作；慢想負責排序列並切好當前大動作。
- 學習期動作須拆至「照著做不用想」。

【進場是必要大動作】
- 每次必做且流程固定，須用 `寫步驟` 記錄細步驟。
- 穩定後用 `{"t":"錄成程序","名":"進場","秒":180}` 錄成程式。

【兩層思考機制】
- 快思（10 秒）：負責移動與眼前小問題（開門、按提示、補狀態）。不負責方向決策。
- 慢想（2 分鐘，每 12 輪）：負責方向決策。需想四事：1. 現在在哪 2. 要去哪及原因 3. 上一步成效 4. 接下來三步。結果寫入【慢想排出來的計畫】。
- 配合：慢想定方向，快思執行。快思每輪僅推進當前步，完成送 `{"t":"下一步"}`。
- 若計畫失效（路死、目標不在、狀況變），送 `{"t":"重想"}` 觸發不限時慢想。
- 好的步驟須具體（用視角度數、XY 座標），避免模糊願望。

【慢想排程格式（09/14 改）】
- 慢想須排：當前大動作、詳細步驟、下一個大動作。
- 面板顯示：總步數、當前步、下一步。
- 執行：每輪推進 👉 步；完成送 `{"t":"下一步"}`；全完送 `{"t":"重想"}`。
- 若發現位置錯誤或計畫失效，送 `{"t":"重想"}`。

【步數預算（2026-09-21 定）】
- 切 N 步即承諾 N×2 輪內完成。
- 超支（>N×2 輪）：扣 3 分，每多拖 3 輪再扣，並當場檢討。
- 預算內完成：僅紀錄，不加分。
- 超支處理：1. 已做到送 `{"t":"這步做完"}`；2. 做不到送 `{"t":"寫步驟"}` 重切（更少步驟）。
- 禁止拖著不動（超支扣罰＋原地空轉扣 100）。
- 一步標準：兩輪內可完成。避免過細（如「修水平」），應合併為「轉頭並走到目標」。

【工作流程化（2026-09-27 交代）】
- 成功一次後，拆成工作流程：大動作序列 + 細步驟。
- 寫法：`{"t":"排大動作","主任務":"目標","序列":["動作1","動作2"]}`；`{"t":"寫步驟","大動作":"名","步驟":["步1","步2"]}`。
- 執行：完成一步送 `{"t":"這步做完"}`；完成大動作送 `{"t":"大動作完成"}`。
- 效益：照流程執行時，程式跳過例行慢想（省 1 分鐘）；僅卡住時才叫慢想。
- 下次遇同事直接用舊流程；順序錯則用 `寫步驟` 修正。
