# 2026-09-18（週五）

## OCR 換成 Windows 內建（繁體）

### 做了什麼
- 使用者問「不能像 iPhone 直接從畫面擷取字嗎？為什麼成功率那麼低？」→ 實測後換引擎。
- `local_text.py` 加入 Windows.Media.Ocr（zh-Hant-TW）後端，`engine="auto"`：
  先用 Windows OCR，某一幀讀不到東西時同輪自動退回 rapidocr（兩顆互補）。
  Windows OCR 吃原尺寸最準，不再縮到 1536；漢字逐字斷開用 `_join_cjk()` 併回來。
- `flow_agent.py` 的 TextEyes 改 `interval=0.8`（快十倍，字更接近「現在」）。

### 解決什麼
- rapidocr 是 PP-OCRv3 mobile、訓練資料以簡體為主，繁體被對到形近簡體字：
  開始遊戲→朋始游战／朋始戴、配對→配封、殭屍→疆屁、大廳→大鹿。
  點字比對不到按鈕 → 他退回猜座標 → 點不中 → 空轉扣分。
  09/18 08:15~10:14 這兩小時「找不到字」78 次、點字只有 8 次、得分零成長。

### 驗證（同一張畫面）
| 引擎 | 耗時 | 讀到 |
|---|---|---|
| rapidocr @1536 | 1090 ms | 朋始戴 0.50、320874、88 |
| **Windows OCR** | **62~102 ms** | **開始遊戲、試槍**（完全正確） |
- 端到端：TextEyes 平均 102 ms／次；點字比對「開始遊戲」→ 完全符合。
- 重啟後前 2 分鐘：點字 3 次、找不到 1 次（換之前是 8:78）。

### 踩到的坑
- `pip install winsdk` 在 Python 3.13 **編譯失敗**（沒有 wheel）→ 改裝 PyWinRT 的分包
  `winrt-runtime` + `winrt-Windows.{Media.Ocr,Globalization,Graphics.Imaging,Storage.Streams}`，有 3.13 的 wheel。
  程式兩種 import 路徑都支援（winrt 優先、winsdk 後備）。
- PyWinRT 分包沒有 `SoftwareBitmap.create_copy_from_buffer` 靜態方法 →
  改用建構子 `SoftwareBitmap(fmt,w,h,alpha)` + `copy_from_buffer(buf)`。
- 非同步不要用 asyncio（每輪起事件迴圈更貴）→ 直接輪詢 `op.status`，5 秒硬截止。

`local_text.py`（備份 `.bak_winocr`）、`flow_agent.py`、新裝的 winrt 分包。
