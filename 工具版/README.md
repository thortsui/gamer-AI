## 一、跟舊版差在哪

| | 舊版 flow_agent | 工具版 tool_agent |
|---|---|---|
| 每輪預設給他 | 36 份文件＋程式算的 40 多個儀表 | **四件事**：他是誰、玩什麼遊戲、使用者給的目標、工具清單（一行一個） |
| 文件 | 全部塞進 system | 每份是一個工具，他要才 `讀文件(名稱)` |
| 動作 | JSON dict（`{"t":"key","k":"w","d":0.6}`） | 工具呼叫 `前進(0.6)`、`視角左(30)`（視角用**度**，不用像素） |
| 意外 | 寫在文件裡要他自己拼 | 包成工具：`180度轉頭`、`脫困`、`關掉面板`、`退出重進`、`死亡重生`、`迷路` |
| 程式替他做的 | 很多（拆兩段、帶路、修水平、擋動作…） | **沒有**：程式只執行他點名的工具，把結果回給他 |
| 字數 | system 64k＋user 26k | system 約 3k，user ＝ 上一輪工具回傳＋最近三輪摘要 |

原則照舊：**不替他玩**（工具只是手腳與書架，拿哪本、怎麼走是他的事）、**告訴就是告訴**（沒有賞罰、沒有擋動作）、鐵律只剩「不花錢」。

## 二、他每一輪看到什麼

1. **system（固定，約 3k 字）**
   - 他是誰：`你是 gamer AI，正在玩 Roblox「<遊戲>」`（`核心/共用/00_身分與現在的任務.md`）
   - 玩什麼遊戲：`專案/<遊戲>/遊戲.json` 的名稱／place；詳細的要自己 `遊戲介紹(遊戲名)`
   - 使用者給的目標：`專案/<遊戲>/記憶/任務指示.txt` 原文
   - 鐵律：不花錢；`看到` 欄只寫儀器讀數；表格式寫法（`核心/共用/99_鐵律與輸出格式.md` 前兩段）
   - **工具清單**：每個工具一行 `名稱(參數)｜用途`，分八類（見 `工具目錄.json`）。要細節就 `工具說明(名稱)`。
2. **user（每輪變）**
   - 現在這一張畫面（一定給；眼睛不是工具，是他的眼睛）
   - 【工具回傳】上一輪他叫的每個工具回了什麼（文件全文、OCR 的字、YOLO 框、動作有沒有做成、看四周的四張圖）
   - 【最近三輪】看到→想→用了什麼→結果
   - 輸出格式一句
3. **他回什麼**
   ```json
   {"看到":"儀器讀數(<=20字)",
    "想":"因為:…｜所以要:…｜動作:…｜結果應該是:…",
    "用":["前進(0.6)","讀字"]}
   ```
   `用` 最多 3 個，字串 `名稱(參數)` 或 `{"工具":"記筆記","參數":{"內容":"…"}}` 都收。程式照順序執行，結果下一輪回給他。

## 三、工具怎麼定義（`工具目錄.json`）

每個工具五個欄位：
```json
{"名稱":"180度轉頭","類別":"視角",
 "用途":"卡在牆壁上、需要直接看背後",
 "用法":"180度轉頭",
 "參數":{},
 "回傳":"轉完之後的新畫面（下一輪就是）",
 "實作":"turn(180)"}
```
- **用途**＝什麼時候該用（他挑工具就看這一欄）。
- **用法**＝怎麼寫。括號裡一個量，跟 10/14 的速記同一套。
- **實作**＝程式對應的函式，或 `文件:<路徑>`（純粹把檔案讀給他）、或 `未實作`（目錄先列、程式還沒做，他叫了會收到「未實作」）。
- 要加工具：目錄加一筆＋`tool_agent.py` 的 `Tools` 加一個同名方法。文件類不用寫程式。

八類：文件（載入知識）／看（讀字、找東西、看四周）／移動（秒）／視角（度）／互動（按、點、點字）／意外（180度轉頭、脫困、關掉面板、退出重進、死亡重生、迷路、付費視窗）／記憶（寫）／流程（這步做完、任務完成、放棄）。

## 三之二、大任務與自訂工具（使用者 10/15 01:0x 加的兩條）

**每次導入的只有前面那些（四件事）加上目前的大任務；執行完大任務再清空、接下一個。**
- 他先用 `設大任務(名稱,成功條件)` 定一件大事；之後每一輪的 user 面板＝【目前的大任務】＋【工具回傳】＋【這個大任務到目前為止】（最多六輪摘要）。
- `大任務完成(結果)` → 程式把這個任務期間的工具回傳與輪次摘要全部清空；`排大任務(A→B→C)` 排過的自動接上，沒有就再 `設大任務`。
- 紀錄：`記憶/工具版/大任務.md`。

**遇到自己不知道、或工具清單沒列出來的問題：想這件事該動用哪個工具，並列入那個工具之後的使用名單。**
- 既有工具做得到、只是用途沒寫這情況 → `補用途(工具,情況)`：下一輪清單上那個工具的用途就多一句「也用在：…」。
- 沒有任何工具做得到 → `新工具(名稱,用途,做法)`：做法只能用現有工具接起來（`後退(0.4)→視角右(90)→讀字`），程式會檢查每一步都是清單上的工具；定義完它就在清單裡（標「你自己定義的」），下一輪就能叫，叫了程式照做法一個一個做。
- 兩者都存 `專案/<遊戲>/記憶/工具版/自訂工具.json`，開機與每輪都合併進清單。這是他自己的記憶檔，照規矩我們不改它。

## 三之三、開工先量、每次都對照實測（使用者 10/15 01:3x）

「他一開始還是需要量測所有的數據，來確保他使用工具出來的結果和他腦中的是一致的。」
- 新類別【校準】：`量畫面`（尺寸、目前刻度、換算）、`量刻度`（程式帶他水平轉一圈量每度 dx、上下掃全程量每度 dy，寫 `記憶/視角校準.json`，鏡頭轉回起點）。
- 每一次 `視角左/右/上/下`、`180度轉頭` 的回傳都附 **預期 vs 實測**：預期幾度（送了多少 dx）、畫面景物實測位移佔畫面寬幾 %、畫面變化量；樣本記 `記憶/工具版/刻度樣本.md`。移動工具回傳畫面變化量。對不上他就該重量。
- system 加【開工先量】一段：登入／重進／畫面大小變了，第一件事 量畫面、量刻度。這是告訴他，程式不強制。

### 開工數值逐一回報（使用者 10/15 01:5x：「還是要按照之前我要求的幾個數值逐一回報」）
- `開工測試` 一鍵：程式依序量 ①畫面尺寸 ②每度 dx ③每度 dy（轉一圈、上下掃）④深度比例（走 1 秒、量畫面中央放大幾倍），逐項列出回傳；⑤第幾人稱由他看畫面用 `回報人稱(第幾人稱)` 回報。
- 面板每輪第一行【開工數值】顯示五項（沒量就寫「還沒量，第一件事開工測試」）。stdout 印「🧪 開工測試：…」跟舊版一樣看得到。紀錄 `記憶/工具版/開工數值.md`、校準寫 `記憶/視角校準.json`。
- `量比例` 可單獨重量第 ④ 項；`量刻度`、`量畫面` 單獨重量 ②③①。

### 10/15 10:5x 精簡（使用者：「按 為什麼需要秒」「點字確認字的判斷正確嗎」「脫困不要，改成轉 180 單位照他計算結果直接輸入……需要更多簡潔的方式」）
- 工具 54 → 44 個。視角只剩 `轉(度)`（正右負左，他算好直接填，可到 ±180，大角度程式自動分段）與 `仰(度)`（正上負下）；移動 `走(秒)`、`退(秒)`、`左移`、`右移`、`跳`；`按(鍵)` 不帶秒（一下 0.15 秒），`長按(鍵,秒)` 預設 1.5；`關掉` 合併 關掉面板＋付費視窗。拿掉：脫困、迷路、死亡重生、180度轉頭、視角上下左右、走到／修水平／量牆距（未實作的不列）。
- 舊名字（前進／後退／視角左右上下／180度轉頭／關掉面板／付費視窗／look）留作**隱藏別名**，他照舊寫也能解析，但清單上不列。
- 點字：統計 56 次只找到 14 次（找到的全對），42 次是 OCR 讀歪 → 改用主專案 `zh_text.find` 繁簡／形近字模糊比對（相似度 ≥0.6），回傳附相似度與怎麼中的；真正的把關仍是下一輪放大圖＋確認點。

## 四、程式 `tool_agent.py`

```
python 工具版/tool_agent.py --game 動物醫院 --dry-run --image <截圖> --rounds 1   # 離線考一輪：不碰遊戲
python 工具版/tool_agent.py --game 動物醫院 --dry-run --rounds 20                  # 抓真畫面、只印不做
python 工具版/tool_agent.py --game 動物醫院 --live --rounds 200                    # 真的按（舊版代理要先停）
```
- 大腦：`http://192.168.0.126:8888/v1`，模型名自動抓（現在是 `gamer-27b-ft-run3`）；推理模式跟舊版快思一樣（`快思推理`，low）。
- 視角換算用 `專案/<遊戲>/記憶/視角校準.json`（每度 dx 2.5／dy 3.65；沒有就預設 2.5／3.65）。
- 每輪紀錄：`專案/<遊戲>/記憶/工具版/YYYY-MM-DD.jsonl`（看到、想、用了什麼、每個工具回傳、推理全文）。
- **`--live` 跟舊版代理不能同時跑**（會搶鍵盤滑鼠）。
