SITCON 2027 投稿：複製貼上用（2026-11-26，大綱只寫方向、順序照簡報 v14k）
每格標題下面那一段就是要貼的內容。（公開版：已拿掉電子郵件、手機、其他聯絡方式）

【1. 投稿類型】
Presentation（40 分鐘：30 分鐘議程＋10 分鐘問答）

【2. 題目（20 字以內）】
打造一個自己學會玩遊戲的代理式AI

【3. 摘要（建議 150–250 字）】
現在的 AI 很強，但它能像真人一樣玩遊戲嗎？在不讀遊戲內部資料、只靠「看螢幕截圖」，且和正常人一樣用「鍵盤滑鼠」的情況下，也能順利地玩嗎？我製作了一個 Agent，搭配地端模型，在沒攻略之下挑戰《Roblox 動物醫院》遊戲。這場將從四個方面拆解 Agent 怎麼玩遊戲：視覺，如何看懂畫面上的東西；思考，模型在思考時想了什麼；操作，如何進行 Computer Use；學習，如何讓 Agent 從零自己學會玩一款遊戲。

【4. 演講大綱】
0–3 分（3 分）　一、開場：現在的 AI 能對話、能看懂圖片、能寫程式，但它能否像人類一樣看著畫面、操作電腦解決問題，如同人類從零開始學會玩一款遊戲？AI 現在能做那麼多事情，我好奇它能不能用人類的方式自行學習，並且玩遊戲，因此我決定自己製作一個 Agent，並定下實驗條件：只提供遊戲截圖、只開放鍵盤與滑鼠、不氪金也不給攻略。
3–9 分（6 分）　二、我的第一版 Agent：先對照人是如何玩遊戲的，再說明第一版的做法：怎麼玩全部用 System prompt 告訴它，包含身分、規則、操作與研究新遊戲的方法；任務拆成大、中、小三層；視覺由另一個視覺模型（YOLO）框選物品，再由程式把畫面轉成文字並推算位置；操作的數值與行走路線由程式事先決定；失誤時以扣分機制強制它檢討。接著把這些整理成第一版每一輪的流程，最後說明第一版的成績，並依序分析它在看懂畫面、讀取 System prompt、記住學過的東西與按鍵操作上出了什麼問題。
9–26 分（17 分）　三、第二版 Agent：先把第一版的問題歸納成四類難題，再介紹第二版改成 LLM 加上 Tool use 的做法，以及每一輪的 Agentic loop：LLM 用 Tool use 寫出工具名稱與參數，程式偵測到後才呼叫對應的工具，經過 Harness 的限制後輸出成鍵盤滑鼠操作，結果再以文字回傳給 LLM；與預期不符就反思，做對了就寫入長期記憶。接著依簡報順序說明各項改變。量測與視覺：操作數值從事先寫死，改成每局開局時現場量測並驗證，動作結果改以文字回傳，並說明視覺工具修正前後的準確度變化，以及實測中仍會出現的失誤。工具：每個動作都做成獨立的工具，被呼叫時使用開局量測出的數值，並以實測片段說明模型如何靠工具一步步移動；地點改用周圍特徵物的相對位置記錄；工具修改後都必須通過 Regression test 才上線。思考：System prompt 大幅縮短，任務改由 LLM 自己規劃，每輪先寫下預期，下一輪再自我驗證，不符就反思，並以實測片段說明它如何從失敗中自己修正。學習：記憶分成準則、截圖與清單三種長期記憶，說明準則如何寫入、如何在需要時檢索，以及寫入後實際被用上的情形。知識的選用：知識不再全部寫進 System prompt，只保留最基本的說明；工具分類並分層載入，LLM 需要哪一類才展開哪一類，以減少每輪的 Context。接著把以上整理成第二版的 Agentic AI 架構，說明學習從被程式扣分才寫檢討，改成結果不符預期時當輪自己寫下反思、卡住或收工時再整體反思一次，需要時才檢索記憶的自我改進方式。最後說明第二版的初步成效，包括每輪所需時間與按鍵互動成功率的變化，以及仍然存在的問題。
26–30 分（4 分）　四、結果的比較與分析：比較第一版與第二版的結果，比較的項目包括完成的任務數、按鍵互動成功率、每一輪所需的時間、重新進局所需的時間、移動有反應的比例、自己寫下的筆記與小任務數，以及自我驗證的通過率，並分析每一項改變有沒有成效。最後反思這套做法還能改進的地方：速度仍不夠快、自我驗證的準確度還要加強、記憶需要整理以避免越記越多與互相矛盾，以及各項改變的成效該如何分開驗證。
30–40 分（10 分）　問答

【5. 目標受眾】
想學習 Agentic AI 如何解決複雜的電腦操作任務的人，好奇如何讓 Agentic AI 從零開始學會玩遊戲的人

【6. 先備知識】
知道遊戲怎麼玩，以及稍微知道大語言模型（ChatGPT）在做什麼的基礎知識

【7. 主題標籤（1–4 個）】
Agentic AI、AI workflow、大語言模型、Computer Use

【8. 詳細說明（下面五小段依序貼，可以一段一段複製）】

【為什麼想講】
我好奇：現在的 AI 那麼強，能對話、能看懂圖片、能寫程式，也會做簡報，幾乎可以完全操作電腦，為什麼還很少看到能像人一樣玩遊戲的 AI Agent？它能不能像人類一樣看著畫面、用鍵盤滑鼠，從零開始用人類的方式自行學習，並且玩遊戲？我自己實驗過，發現它真的玩不了，所以想知道為什麼，以及要怎麼讓它玩得了。玩遊戲需要同時看懂畫面、判斷下一步、操作鍵盤滑鼠，還要記住學過的東西，剛好是測試 AI 能不能像人一樣自主完成一件事的好題目。也因為這樣，我最後把它做成一套 Agentic AI：讓模型自己研究遊戲，而不是由程式一步一步替它做。

【想傳達什麼】
第一，雖然每個 AI 都不太一樣，但都能接上同一套工具開始玩，只是模型不同，效果還是會有差。第二，工具要怎麼設計才符合 AI，也就是要用 AI 的方式去思考：AI 看圖是在比對看過的圖片，思考是逐字預測下一個字，操作是寫出文字，由程式偵測後呼叫工具按鍵，學習是寫入記憶再檢索，它的基礎和人不一樣。製作工具時有哪些地方要注意，例如 System prompt 不能太長，因為一長串字裡，模型只對前面和後面的內容比較記得，中間的規則容易被忽略；又例如玩遊戲時讓它走一步就停三秒，只看停下來的那張畫面。第三，一個 Agent 不是只有模型本身，而是模型加上一層 Harness，在 Agentic loop 裡自己規劃、用 Tool use 寫出要用的工具、驗證結果，再把學到的寫進記憶；工具和記憶怎麼設計，決定它玩不玩得起來。希望聽完之後，大家知道怎麼做一套更適合讓 AI 使用的工具，也能更正確地想像 AI 做一件事的具體步驟；下次覺得 AI 怎麼做不到的時候，可以試著用它的方式想一遍。這些不是只能用在遊戲，想讓 AI 幫你做別的事，也用得上。

【我的做法跟別人不一樣的地方】
我做的是一套 Agent 架構和工具，不是新的模型，所以換一個模型也能接得上。我給它的條件跟人一樣：只提供遊戲截圖、只能透過鍵盤滑鼠操作，不讀取遊戲內部資料、不修改遊戲、不氪金，也不提供攻略，怎麼玩一個字都不教；氪金與離開遊戲的按鈕，由 Harness 擋下。模型本身只會輸出文字，所以每一個動作都是它用 Tool use 寫出工具名稱和數值，例如「走(0.5)」，程式偵測到這段文字後，才呼叫走路的工具按住 W 鍵半秒，並把結果寫成文字回傳給它。和直接把截圖丟給模型不同，我讓它每一輪先寫下「結果應該是什麼」，下一輪自己驗證，把做對的方法寫進長期記憶，需要時再檢索；它是靠這些自己寫下的紀錄做到自我改進，模型本身沒有改變。

【議程架構】
照演講大綱分成四段：開場（3 分鐘）、我的第一版 Agent（6 分鐘）、第二版 Agent（17 分鐘）、結果的比較與分析（4 分鐘），最後 10 分鐘問答。第一版說明怎麼用 System prompt 告訴它怎麼玩、每一輪的流程，以及問題出在哪；第二版先把問題歸納成四類難題，再介紹每一輪的 Agentic loop，接著照簡報的順序講量測與視覺、工具、思考、學習、知識的選用改成什麼、怎麼做，以及初步成效；第四段再逐項比較兩版的結果，分析每一項改變有沒有成效，整理模型和人在四個方面的差異，接著帶回 AI 玩遊戲的具體流程，和開場的問題對比，最後反思還能改進的地方。聽的人不用記住一百多個工具，只要跟著每一輪的流程走。簡報裡也放了實際錄下來的遊戲片段，成功和失敗的都有，例如它自己走到櫃檯、對著垃圾桶按 E 卻跳出無法丟棄的提示、失敗後自己寫下反思，讓大家直接看到它在遊戲裡是怎麼判斷、怎麼出錯的。

【兩版的做法與結果】
第一版：怎麼玩全部用 System prompt 告訴它，身分、總目標、規則、操作與移動方法、研究新遊戲的方式都寫進去，共 64,703 字。任務拆成大、中、小三層，一次只學一個中任務，右上角的任務字換了才算完成。視覺由程式代勞：另一個視覺模型（YOLO）框出畫面上的物品，程式把畫面轉成文字，再照地圖推算它的位置。操作的數值事先寫死：轉向角度寫在 System prompt 裡，行走照程式算好的地圖路線，互動一律走到東西前面長按 E 鍵。一失誤就由程式扣分，強制它寫檢討，再把檢討貼回面板，每一輪重讀。整理成每一輪的流程就是：程式截取畫面、照 System prompt 寫下動作、被扣分就寫檢討、經過 Harness 擋下氪金與離開遊戲、程式按鍵再回傳結果。結果兩天下來完成 0 件任務。依序看問題出在哪：不認識正前方是哪一個物品，地形相似時容易認錯位置，也量不出物品的距離；System prompt 加上當局的資訊會超過模型一次能讀取的上限，寫在中間的規則容易被忽略；檢討越寫越長，走過的路卻沒記住，死掉回大廳後平均要 61 分鐘才能再進局；按 E 58 次只有 3 次有反應，地圖上它以為的地方不是實際位置，停下後也沒確認是否對準目標就按 E。
第二版：先把第一版的問題歸納成四類難題：畫面上的距離量不準、提示越寫越長被忽略、按鍵後無法確認結果、走過的路下次就忘記。第二版每一輪是一個 Agentic loop：LLM 只會寫字，它用 Tool use 寫出工具名稱與參數，例如「走(0.5)」，程式偵測到這段文字後，才呼叫對應的工具，工具把它轉成按鍵，經過 Harness 擋下氪金與離開遊戲後才輸出到鍵盤滑鼠，結果再以文字回傳；與預期不符就進行反思，做對了就寫入長期記憶。量測與視覺：每次開局現場量五項參數：畫面大小、轉一度要拖多少、走一步畫面放大幾倍、第幾人稱、各按鍵的作用；量完照數值轉一圈、走一步再退回來，回到原點才算驗證通過；動作的結果也改以文字回傳，但實測中仍有量錯或回傳錯的時候，例如指令轉 -50 度實際只轉 -9 度，或回傳說已經水平，其實在看地板。視覺工具修準後，走一步量得出距離的比例從 44% 升到 92%，視角對準目標的比例從 38% 升到 88%，但實測中它仍會想對準蓋印機卻對到咖啡機。工具：每個動作都做成工具，LLM 用 Tool use 寫出指令，程式偵測到後才呼叫它，並用前面量出來的數值操作，例如「走(0.5)」就是按住 W 鍵半秒；它一輪一輪寫下走路的指令，自己走到櫃檯前。地點則改用相對位置記錄，例如它自己寫下的「左藍藥架、中門、右綠架」。工具前後修改了一百多次，每次都必須通過 Regression test 才上線。思考：System prompt 從 64,703 字減到 3,175 字，任務改由 LLM 自己規劃，每一輪先寫下看到什麼、這輪要用哪些工具、結果應該是什麼，下一輪再自我驗證：例如它預期會走到電腦前，下一輪發現其實被擋住沒有動；實測中它按 E 失敗後改按 1 拿出蓋印機，也會轉頭再轉回來，確認那是畫面上的任務字，而不是場景裡的物體。學習：記憶分成準則（成功的做法）、截圖（物品的長相）與清單（可互動的物品）三種長期記憶，平常不放在面板上；準則每條都由它自己寫，寫入前先比對舊的準則，需要時才檢索；例如它在電腦上註冊成功後記下做法，當晚再遇到同一件事，查到準則後約一分鐘任務字就更新了。知識的選用：知識不再全部寫進 System prompt，System prompt 只留它是誰、玩什麼、目標、有哪些工具四件事；一百多個工具分成九類，涵蓋看與找、任務流程、場景切換、移動與視角、互動、意外處理、認識新東西、查詢與文件，平常只列每一類的一行概述，LLM 寫出要打開哪一類，那一類的完整工具才展開，例如打開「看與找」才看得到找東西、估距離、讀字的工具；這樣只有要用的那一類才展開，每一輪的 Context 大約少了 13,000 字。接著把這些改變整理成第二版的 Agentic AI 架構：知識拆成工具、操作交給工具執行、數值開局時現場量、記憶存成檔案需要時才查；學習也從被程式扣分才寫檢討，改成結果不符預期時當輪自己寫下反思，卡住或收工時再整體反思一次，需要時再檢索記憶，藉此越做越好。最後看初步成效：System prompt 縮短後每輪所需時間變短，但時間主要花在逐字生成，每一輪仍要中位數 23 秒；按鍵互動成功率從約 5% 提高到 45%，但實測中它仍會對著垃圾桶按 E，跳出手上的蓋印機無法丟棄的提示。
結果的比較與分析：逐項比較兩版的結果，看每一項改變具體有沒有成效。有成效的：完成任務從第一版兩天 0 件，到第二版用地端 27B 模型最好的一局完成 6 件；按鍵互動成功率從約 5% 提高到 45%；每一輪從 10 至 90 秒縮短到中位數 23 秒；重新進局從死掉後平均 61 分鐘，到清空記憶後 12 分鐘自己進局；移動有反應 100%，還自己記下 23 條筆記、設了 10 個小任務。沒有成效的：工具分層後每一輪的 Context 大約少了 13,000 字，但自我驗證的通過率前後都是 24%。接著用地端 27B 模型套上工具實測一局單人局：錄影裡它第一次嘗試就進到醫院，也能認出櫃檯、自己走過去；這一局最後還沒蓋到印就理智歸零死亡；失敗之後，它自己寫下反思，記下錯在哪，以及死亡畫面上哪個按鈕可以點、哪個不要碰。再整理模型和人在四個方面的差異：看圖是比對看過的圖片，思考是逐字預測下一個字，操作是寫出文字，由程式偵測後呼叫工具按鍵，學習是寫入記憶再檢索；所以下次覺得 AI 做不到的時候，可以用它的方式想一遍，例如走一步就停三秒，只看停下來的那張畫面。接著帶回 AI 玩遊戲的具體流程：它看截圖、規劃、用 Tool use 寫出要用的工具、由程式偵測後呼叫工具，經過 Harness 操作鍵盤滑鼠、下一輪自我驗證、卡住時反思、把學到的寫入長期記憶，拿這個流程和開場的問題「AI 能不能不靠攻略，自己學會玩遊戲」對比。最後反思還能改進的地方：第一是速度，每一輪的時間主要花在逐字生成，中位數仍要 23 秒，還不夠快；第二是自我驗證的準確度，工具分層前後通過率都是 24%，它判斷自己有沒有做對的能力還要加強；第三是記憶的整理，準則越記越多，還會出現互相矛盾的條目；第四是驗證的方法，第二版的幾項改變是同時改的，沒有一項單獨驗證過，所以分不出各自貢獻多少，反思有沒有讓它少犯同樣的錯也還沒有單獨量過，之後可以一次只改一項再比較。
